2. 思维树（Tree-of-Thought，ToT）

核心思想

不只尝试一条路径，而是生成多个候选方案，对它们进行评估，再选择最优方案。

经典 Demo：24 点游戏

问题：

使用数字 4、9、10、13 和四则运算得到 24。

候选路径：

继续展开路径 B：

ToT 的关键不是一次找到答案，而是：

  1. 生成多个候选路径。
  2. 判断哪些路径更有希望。
  3. 剪掉低价值路径。
  4. 继续展开高价值路径。

维度 含义
可行性 当前工具是否能够执行
准确性 是否能正确完成任务
成本 时间、Token 和工具调用成本
风险 是否可能产生副作用
可验证性 结果是否容易检查

适用场景

  • 多方案决策
  • Agent 路由
  • 创意内容生成
  • 复杂数学问题
  • 失败后切换备选方案

3. 思维图（Graph-of-Thought，GoT）

核心思想

思考过程不仅可以分支，还可以合并、交叉引用和回到之前的节点。

与 ToT 的区别：

  • ToT 主要从多条路径中选择一条。
  • GoT 可以合并多条路径的结果。
  • GoT 允许验证失败后形成回环。

5. 反思与自纠（Reflexion / Self-Refine）

核心思想

完成任务后检查结果，分析失败原因，再根据反馈进行修正。

Agent 设计实践

设计要点

  1. 设置最大重试次数。
  2. 优先使用测试和规则验证结果。
  3. 每次重试必须改变方案或参数。
  4. 保存具体失败原因，不保存无关内容。
  5. 连续失败时停止并说明原因。

适用场景

  • 代码生成和自动修复
  • 工具调用失败重试
  • 文章和报告优化
  • 输出格式检查
  • 数据质量检查

6. 先规划后执行（Plan-and-Solve）

核心思想

先制定完整计划，再按照计划执行。执行结果发生变化时，只调整后续计划。

经典 Demo：解应用题

问题：

一个水池有两个进水管。A 管每小时注满水池的 $1/3$，B 管每小时注满水池的 $1/6$。两个水管同时打开，多久能注满？

Plan

Solve

$$
\frac{1}{3}+\frac{1}{6}=\frac{1}{2}
$$

两个水管每小时注满水池的 $\frac{1}{2}$：

$$
1\div\frac{1}{2}=2
$$

答案：2 小时。

Agent 设计实践

适用场景

  • 目标明确的复杂任务
  • 研究报告
  • 软件开发
  • 数据分析
  • 自动化运维

7. 语言 Agent 树搜索（LATS）

核心思想

LATS 将候选动作搜索、状态评估、反思和回溯结合起来。

当一条路径失败时，Agent 会退回之前的状态，尝试其他路径。

技术对比

技术 一句话理解 Agent 中的作用 复杂度
CoT 分步骤分析 基础推理与工具决策 低
ToT 多条路径选最优 决策与路由 中
GoT 分支可以合并和回环 多 Agent 协作 高
任务分解 把大任务拆成小任务 Planner 中
Reflexion 失败后反思并修正 质量保障与恢复 中
Plan-and-Solve 先规划，再执行 流程控制 中
LATS 搜索、反思与回溯 自主探索 高

如何选择

任务需求 推荐技术
简单分析或工具选择 CoT
存在多个候选方案 ToT
复杂任务需要拆分 Task Decomposition
需要先制定完整计划 Plan-and-Solve
输出需要测试和修改 Reflexion
多 Agent 或多源结果融合 GoT
需要探索失败路径并回退 LATS

推荐的最小组合

多数 Agent 不需要同时使用所有技术。

建议从以下组合开始：

只有出现以下需求时，再增加复杂能力：

  • 有多个可行方案时，引入 ToT。
  • 需要多 Agent 协作时，引入 GoT。
  • 需要大量探索和回溯时，引入 LATS。

实施原则

  1. 先定义目标、约束和成功标准。
  2. 将复杂任务拆成可验证的步骤。
  3. 工具调用使用结构化输入和输出。
  4. 优先通过测试、规则和数据验证结果。
  5. 所有重试都必须设置次数、时间和成本上限。
  6. 只有关键决策才生成多个候选方案。
  7. 简单任务不要使用复杂搜索架构。
  8. 输出结论和必要依据，不依赖暴露完整内部推理。
  9. 保存工具调用、执行结果和失败原因，便于追踪。
  10. 多次失败后停止执行，并明确说明阻塞原因。
