CrewAI 教程

CrewAI 教程

1. CrewAI 是什么

CrewAI 是一个多智能体协作框架，用来把复杂任务拆给多个 AI 角色完成。

它适合这类任务：

  • 调研
  • 写报告
  • 多步骤自动化
  • 数据分析
  • 多角色协作流程

它的核心不是“多模型聊天”，而是把任务拆成：

  • 谁来做
  • 做什么
  • 前后怎么衔接
  • 结果怎么校验
  • 整个流程怎么控制

2. 核心概念

Agent

执行者，相当于团队成员。

核心字段：

  • role：角色
  • goal：目标
  • backstory：工作原则和背景

常用参数：

  • llm：模型
  • tools：工具
  • reasoning：先思考再执行
  • allow_delegation：允许委派
  • max_iter：最大迭代次数

Task

任务单，告诉 Agent 做什么。

核心字段：

  • description：任务说明
  • expected_output：输出要求

常用参数：

  • agent：谁执行
  • context：依赖前置任务
  • output_file：输出文件
  • markdown：Markdown 输出
  • guardrail：结果校验
  • human_input：人工审核

Crew

团队，负责组织多个 Agent 和 Task。

决定：

  • 哪些 Agent 参与
  • 哪些 Task 执行
  • 用什么流程执行
  • 是否开启 memory、planning、cache

Flow

业务工作流，负责更外层控制。

适合：

  • 多个 Crew 串联
  • 条件分支
  • 状态保存
  • 重试
  • 人工审核

Tool

Agent 使用的外部能力。

例如：

  • 搜索网页
  • 读文件
  • 查数据库
  • 调 API
  • 执行 Python

Knowledge

静态知识库。

例如文档、PDF、手册、FAQ。

Memory

动态记忆。

例如用户偏好、历史决定、前面任务结果。

3. 它们之间的关系

  • Agent：谁来做
  • Task：做什么
  • Crew：团队怎么协作
  • Flow：整个流程怎么运行
  • Tool：如何访问外部世界
  • Knowledge：静态资料
  • Memory：动态经验

6. Agent 怎么设计

role

不要写太泛。

差：

  • Assistant

好：

  • Market Research Analyst
  • Technical Writer
  • Pricing Analyst

goal

不是重复任务，而是定义工作目标。

差：

  • Research the topic

好：

  • Find recent, reliable, and useful facts about the topic

backstory

不是写小说，而是写工作原则。

应包含：

  • 优先用什么来源
  • 是否区分事实和预测
  • 遇到不确定信息怎么处理
  • 输出风格是什么

7. Task 怎么设计

一个好 Task 要写清：

  • 做什么
  • 范围是什么
  • 来源要求是什么
  • 输出长什么样
  • 怎样算完成

description

写执行要求。

例如：

  • 时间范围
  • 研究范围
  • 来源标准
  • 禁止事项

expected_output

写结果规格。

例如：

  • 输出几个要点
  • 是否要 Markdown
  • 是否要来源链接
  • 是否要 JSON

8. Task 之间如何传递结果

多任务时，后一个任务通常依赖前一个任务结果。

例如：

  1. research_task：查资料
  2. analysis_task：分析资料
  3. writing_task：写报告

做法：

  • 分析任务读取研究结果
  • 写作任务读取研究和分析结果

CrewAI 用 context 表达这种依赖。

原则：

  • 只传必要上下文
  • 不要把全部结果都塞给后续任务
  • 上下文太多会增加成本和噪音

9. Crew 的两种执行方式

Sequential

顺序执行。

适合：

  • 调研 → 分析 → 写作
  • 提取 → 校验 → 存储

优点：

  • 简单
  • 稳定
  • 易调试

Hierarchical

层级执行，由 Manager 动态分配任务。

适合：

  • 任务无法提前拆清
  • 多角色动态协作

缺点：

  • 更复杂
  • 更贵
  • 更难调试

建议：

  • 默认先用 Sequential
  • 真有必要再用 Hierarchical

10. Tool 怎么用

Tool 是 CrewAI 实用性的关键。

常见工具：

  • 搜索：SerperDevTool
  • 网页：WebsiteSearchTool
  • 文件：FileReadTool
  • PDF：PDFSearchTool
  • 数据库：PGSearchTool
  • 代码：CodeInterpreterTool

  • 工具描述要清楚
  • 高风险工具要谨慎授权
  • 敏感操作不要直接给普通 Agent

11. Knowledge 和 Memory 的区别

Knowledge

静态资料。

例如：

  • API 文档
  • 产品手册
  • PDF 报告

Memory

动态经验。

例如：

  • 用户偏好
  • 已确认的历史决定
  • 前面任务的重要结果

一句话：

  • Knowledge = 运行前准备的资料
  • Memory = 运行中积累的信息

12. Guardrail 是什么

Guardrail 是结果校验规则。

适合检查：

  • 是否缺字段
  • 是否缺来源
  • 是否条数不足
  • 是否格式错误
  • 数值是否超范围

原则：

  • 主观质量交给 Agent 或人工
  • 硬规则交给 Guardrail

13. Flow 什么时候用

  • 多个 Crew 串联

  • 状态保存
  • 重试

14. 运行时会发生什么

crew.kickoff() 后通常会：

  1. 读取输入
  2. 替换变量
  3. 初始化 Agent、Task、Tool
  4. 把 Task 和 Context 传给 Agent
  5. Agent 决定是否调用 Tool
  6. Tool 返回结果
  7. Agent 生成输出
  8. Guardrail 校验
  9. 通过后进入下一个 Task
  10. 返回最终结果

如果结果不好，优先检查：

  • Task 是否写清楚
  • Agent 是否职责明确
  • Tool 是否返回有效数据
  • Context 是否传对
  • 模型是否合适

15. 测试要看什么

不要只看“能不能跑”。

至少看：

  • 结果是否准确
  • 输出是否完整
  • 是否有来源
  • 多次运行是否稳定
  • Tool 成功率
  • 总耗时
  • Token 用量
  • 成本是否可控

16. 安全与权限

只要 Agent 能调用 Tool，就必须注意权限。

原则：

  • 最小权限
  • 参数校验
  • 高风险操作人工确认
  • 日志留痕
  • 敏感能力隔离

特别小心：

  • Shell 执行
  • SQL 执行
  • 删除文件
  • 写数据库
  • 调付款 API
  • 改生产环境

17. 成本优化

高成本通常来自：

  • Agent 太多
  • 任务太碎
  • reasoning 太多
  • 上下文太长
  • 重复搜索
  • 重试过多
  • 全部用大模型

优化方法：

  1. 一个 Agent 能做完就别拆太多
  2. 小任务用小模型
  3. 限制 max_iter
  4. 控制上下文长度
  5. 开启缓存
  6. 固定逻辑交给普通代码
  7. 只在必要时开 reasoning/planning

一句话：

  • 模糊判断交给 Agent
  • 确定规则交给代码

18. 推荐开发顺序

第一步

先做最小版本：

  • 1 个 Agent
  • 1 个 Task
  • 1 个 Tool
  • 1 个 Crew

第二步

再拆职责：

  • 增加分析 Agent
  • 增加写作 Agent
  • 用 context 连接任务

第三步

稳定输出：

  • 结构化输出
  • Guardrail
  • 多轮测试

第四步

补流程控制：

  • Flow
  • 重试
  • 分支
  • 人工审核

第五步

生产化：

  • 日志
  • 权限控制
  • Checkpoint
  • 成本统计

20. 最重要的实践原则

  1. 先设计流程，再设计 Agent
  2. Agent 按职责拆，不按人格拆
  3. Task 一定要写清输出标准
  4. 默认先用 Sequential
  5. Context 只传必要内容
  6. 静态资料放 Knowledge
  7. 动态信息放 Memory
  8. 关键结果尽量结构化
  9. 硬规则一定用 Guardrail
  10. 从最小系统开始，不要一开始就堆满高级功能
