Prompt 工程入门笔记

Prompt 工程

Prompt 工程主要包含五部分：

  1. System Prompt
  2. Zero-shot 与 Few-shot
  3. 角色与约束
  4. 输出格式控制
  5. Prompt 模板管理

5.1 System Prompt

核心思想

System Prompt 用来定义 Agent：

  • 是谁
  • 要完成什么任务
  • 可以做什么
  • 不能做什么
  • 按什么流程工作
  • 以什么格式输出

5.2 Zero-shot 与 Few-shot

核心思想

Zero-shot： 不提供示例，直接描述任务。

Few-shot： 提供少量示例，让模型学习任务规则和输出形式。

使用原则

  1. 示例应正确且具有代表性。
  2. 示例格式必须与目标输出一致。
  3. 优先选择与当前任务相似的示例。
  4. 一般使用 2～5 个示例即可。
  5. 示例过多会增加 Token 成本并干扰模型。

5.3 角色与约束

核心思想

角色定义模型应该以什么视角处理问题，约束定义它必须遵守哪些规则。

经典 Demo：系统架构师

硬约束与软约束

硬约束

必须严格执行，违反时应拦截输出。

软约束

用于引导输出风格，不一定能完全保证。

5.5 Prompt 模板管理

核心思想

Prompt 不应散落在代码中，而应作为可复用、可版本化、可测试的配置进行管理。

经典 Demo

  • 难以测试
  • 修改需要改代码

Prompt 工程五要素

要素 主要作用 关键实践
System Prompt 定义 Agent 的行为 角色、目标、流程、边界
Few-shot 用示例校准模型 选择少量相关示例
角色与约束 控制视角和边界 Prompt 引导加代码检查
输出格式 连接下游程序 Schema 与结构化输出
模板管理 支持复用和迭代 配置化、版本化、测试

完整示例：代码审查 Agent

Agent 流程

工作流程

最佳实践

  1. 明确写出任务目标和成功标准。
  2. 将指令、上下文、示例和用户输入分区。
  3. 简单任务优先使用 Zero-shot。
  4. 格式敏感或规则特殊时使用 Few-shot。
  5. 不要只依赖 Prompt 执行安全约束。
  6. 程序输入优先使用结构化输出。
  7. 对模型输出进行解析和 Schema 验证。
  8. Prompt 使用模板管理并记录版本。
  9. 使用真实测试集评估 Prompt，不凭感觉修改。
  10. 同时关注准确率、延迟和 Token 成本。

核心原则：Prompt 负责引导模型，代码负责验证结果，权限系统负责控制风险。
