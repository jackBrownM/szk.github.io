一、是什么 & 为什么需要

LangGraph 是什么

想象你在画流程图：“先做A，再看情况做B或C，如果不行就回去重做A”。

LangGraph 就是把这种流程图变成可运行的 AI 程序的工具。LangChain 团队出品。

用外卖点单来理解

这个过程有判断、有循环、有调工具，用普通的链式代码写很痛苦，LangGraph 画个图就搞定了。

为什么不直接用 LangChain

场景 用谁
用户问 → AI 答（一问一答） LangChain 够了
用户问 → AI 查资料 → AI 答（RAG） LangChain 够了
用户问 → AI 想 → 调工具 → 看结果 → 再想 → 可能再调 → 最终答 要用 LangGraph
需要人工审核才能继续 要用 LangGraph
多个 AI 协作完成任务 要用 LangGraph

一句话：流程是直线用 LangChain，流程有岔路或回头路用 LangGraph。

二、核心概念

LangGraph 就三样东西，记住这三个就懂了 80%：

用「导航地图」来理解

你的车上带着一个行李箱（State），每到一个城市就往里面放东西或拿东西。

概念 大白话 类比
State（状态） 一个在所有步骤间传来传去的”数据包” 行李箱
Node（节点） 每一步要做的事（一个函数） 每个城市的任务
Edge（边） 步骤之间的连线，决定下一步去哪 城市之间的路
Conditional Edge 根据情况走不同的路 路口的指示牌
START 整个流程的起点 出发地
END 整个流程的终点 目的地
Graph 把上面的全部组合起来 整张地图

三、State（状态）

大白话

State 就是一个字典（dict），里面装着你的 AI 程序运行过程中需要的所有数据。

每个节点拿到这个字典 → 看看里面有什么 → 做点事 → 把结果放回去 → 传给下一个节点。

怎么定义

这就是定义了一个行李箱，里面有三个格子：聊天记录、用户名、步数。

Reducer = 新旧数据怎么合并

问题来了：节点往 State 里放数据时，新数据和旧数据怎么合并？

写法 合并方式 举例
Annotated[list, add_messages] 追加到列表后面 旧的3条消息 + 新的1条 = 4条
Annotated[list, operator.add] 拼接列表 [a,b] + [c] = [a,b,c]
不写 Annotated，直接 str 覆盖旧值 旧的”hello” → 新的”world”

四、Node（节点）

大白话

节点 = 一个普通的 Python 函数。

它接收 State（行李箱），做点事，返回要更新的内容。

注册到图里

节点里可以干啥

想干啥干啥，就是个普通函数：

  • 调用 ChatGPT / Claude 等 LLM
  • 调用外部 API（查天气、查数据库）
  • 做数据处理（解析、计算、格式化）
  • 什么也不做，纯粹用来当路由（看看数据，决定下一步去哪）

五、Edge（边）

大白话

边 = 节点之间的连线，告诉程序”这步做完了下一步做什么”。

普通边：A 做完一定去 B

画出来就是：START → greet → process → END

条件边：A 做完了，看情况去 B 或 C

就像一个路口，函数 decide_next 当路标，指向不同方向。

六、条件分支

用 if-else 做路由

用户问天气 → 走天气节点；问新闻 → 走新闻节点；其他 → 走通用节点。

让 LLM 自己决定走哪条路

让 AI 自己判断用户在问什么，比手写 if-else 更智能。

八、消息与对话

四种消息类型

对话就是这四种消息的列表，来回交替。

add_messages 干了什么

你可能好奇这个 add_messages 有什么特别的？

它做了两件事：

  1. 新消息来了 → 追加到列表末尾（不会丢掉之前的聊天记录）
  2. 如果新消息和某条旧消息 id 一样 → 替换那条旧的（而不是重复添加）

这就是 LangGraph 管理对话历史的核心机制。

对话记忆

State 里的 messages 列表 = 对话记忆。

节点每次返回新消息，自动追加到 messages 里。下一个节点拿到的就是完整的对话历史。

配合 Checkpointer（第十一节）还能跨会话记忆——关掉程序再打开，还记得上次聊了什么。

十一、持久化与 Checkpointer

大白话

Checkpointer = 自动存档。

就像游戏打到一半存个档，下次打开继续。Checkpointer 帮你保存 AI 应用的状态（聊天记录等），关掉程序再打开，还能接着聊。

三个用途

  1. 对话记忆：同一个用户下次来还记得之前聊过什么
  2. 暂停恢复：人工介入时需要存档，人确认后从存档点继续
  3. 时间旅行：回退到之前某个时刻的状态

十四、错误处理与重试

为什么要重试

AI 接口不稳定——网络超时、限频、服务抖动，都可能出错。出错了自动重试比直接崩掉好。

方式一：在函数里自己重试

方式二：LangGraph 内置重试

一行搞定，节点执行失败自动重试 3 次。

方式三：try-except 兜底

出错不崩，给用户一个友好提示。

十七、LangGraph vs LangChain

对比 LangChain LangGraph
流程形状 直线（A→B→C） 任意图（可以分叉、可以回头）
能循环吗 ❌ ✅（Agent 核心能力）
数据怎么传 隐式（上一步输出=下一步输入） 显式 State（清清楚楚）
人工介入 自己实现 内置 interrupt
保存对话 自己实现 内置 Checkpointer
流式输出 基础 多种模式（values/updates/messages）
学习难度 低 中等
适合 简单问答、RAG 复杂 Agent、多步推理、多 Agent

两者关系：LangGraph 是 LangChain 的升级版，底层用的还是 LangChain 的消息类型、LLM 接口、工具定义。LangGraph 不替代 LangChain，而是在它之上增加了图编排能力。

最佳实践（记住这几条就行）

建议 为什么
State 里只放必要的字段 数据太多影响性能，也难维护
一个节点只做一件事 方便调试、复用、替换
列表字段记得用 Reducer 不然新数据会覆盖旧数据
复杂流程拆成子图 模块化，容易理解和测试
LLM 调用一定要加重试 AI 接口经常抽风
生产环境存档用数据库 MemorySaver 重启就没了
限制最大循环次数 防止 Agent 死循环烧钱
接入 Langfuse 做监控 看得见才能优化

防止死循环

Agent 有可能反复调工具停不下来，这个参数是安全阀。

接入监控（Langfuse / LangSmith）

接入后能看到：每个节点的输入输出、耗时、token 用量、报错信息。不接监控等于闭着眼开发。
