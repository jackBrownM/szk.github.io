Redis 入门笔记

一、Redis 是什么？

Redis = Remote Dictionary Server（远程字典服务）

一句话理解：Redis 就是一个把数据放在内存里的超快数据库，像一个巨大的字典/HashMap，你用 key 去存取 value。

核心特点：

  • 数据存在内存中，读写速度 10万+/秒
  • 单线程处理命令（简单高效，无锁竞争，天然线程安全）
  • 所有操作都是原子性的（要么全做，要么不做）
  • 不只是 key-value，支持丰富的数据结构

能干什么：数据库、缓存、消息队列、排行榜、分布式锁、会话管理……

1. String（字符串）—— 最基础、最常用

是什么：一个 key 对应一个 value，value 可以是文字、数字、甚至二进制数据，最大 512MB。

常见用途：缓存、计数器、分布式锁、Session 存储

2. Hash（哈希）—— 存对象最合适

是什么：一个 key 里面有多个 field-value 对，就像一个小字典。非常适合存储对象。

常见用途：存用户信息、购物车、配置项

是什么：按插入顺序排列的字符串列表，可以从两端推入/弹出，像一个双端队列。

4. Set（集合）—— 去重 + 集合运算

是什么：无序、不重复的字符串集合。强项是交集、并集、差集运算。

实际场景 —— 共同好友：

常见用途：标签、共同好友、去重、抽奖

5. Sorted Set / ZSet（有序集合）—— 排行榜神器

是什么：每个成员有一个分数（score），按分数自动排序。去重 + 排序。

实际场景 —— 实时排行榜：

常见用途：排行榜、延迟队列（用时间戳当score）、带权重排序

6. Stream（流）—— 专业消息队列

是什么：Redis 5.0 引入的日志型数据结构，类似 Kafka。支持消费者组、消息确认，比 List 做队列更专业。

对比 List 和 Stream：

特性 List Stream
消息持久化 弹出即删 保留在流中
消费者组 ❌ ✅
消息确认 ❌ ✅ ACK
消息回溯 ❌ ✅

常见用途：事件流、可靠消息队列、日志收集

7. Bitmap（位图）—— 极省内存的统计

是什么：用一个 String 的每一位（bit）来存 0/1，1 亿用户只需 12.5MB。

常见用途：签到统计、活跃用户、在线状态、布隆过滤器

8. HyperLogLog —— 超省内存的去重计数

是什么：用固定 12KB 内存就能统计 2^64 个不同元素的数量，有约 0.81% 误差。

何时用：只需要知道”有多少个不同的XXX”，不需要知道具体是谁，且允许小误差。

9. Geospatial（地理空间）—— 附近的人

常见用途：附近的人/店/车、距离计算

五、过期策略 & 内存淘汰（面试高频）

Redis 怎么删除过期 key？

采用 惰性删除 + 定期删除 双重策略：

策略 怎么做 特点
惰性删除 访问 key 时检查是否过期，过期才删 省 CPU，但可能有大量过期 key 占内存
定期删除 每 100ms 随机抽取一些 key 检查并删除过期的 折中方案，抽样检测

内存满了怎么办？—— 淘汰策略

在 redis.conf 里配置 maxmemory-policy：

策略 含义 推荐场景
noeviction 不淘汰，内存满了直接报错 默认值，数据不能丢的场景
allkeys-lru 所有 key 中淘汰最近最少使用的 ✅ 缓存最常用
volatile-lru 只在设了过期时间的 key 中淘汰 LRU 混合使用（有些key永不过期）
allkeys-lfu 所有 key 中淘汰使用频率最低的 热点数据场景
volatile-lfu 过期 key 中淘汰 LFU
allkeys-random 随机淘汰
volatile-ttl 淘汰剩余 TTL 最短的

六、持久化（数据怎么不丢？）

RDB —— 快照

原理：每隔一段时间，把内存中的所有数据拍个快照存到磁盘（dump.rdb）。

优点 缺点
文件小、恢复快 可能丢几分钟数据
适合做备份 大数据集 fork 耗时

AOF —— 追加日志

原理：每个写命令都追加记录到日志文件，重启时重新执行一遍恢复数据。

什么是 AOF 重写？ 比如 INCR counter 执行了 10000 次，AOF 记了 10000 行。重写后变成一行 SET counter 10000。

优点 缺点
数据几乎不丢 文件比 RDB 大
可读性好（都是命令） 恢复比 RDB 慢

最佳实践

七、事务

⚠️ 注意：Redis 事务不支持回滚！如果某条命令出错，其他命令照样执行。这和 MySQL 事务不一样，它保证的是「一批命令连续执行不被打断」。

八、Pub/Sub（发布/订阅）

特点：

  • at-most-once：消息不保存，离线收不到
  • 跨数据库（db0 发的，db1 也能收到）
  • 需要可靠消息？用 Stream 代替

九、主从复制（读写分离）

原理：一个主节点（写）+ 多个从节点（读），从节点自动同步主节点数据。

要点：

  • 异步复制（主不等从确认），性能高但可能丢数据
  • 从节点默认只读

十、Sentinel 哨兵（自动故障转移）

解决问题：主节点挂了，自动把一个从节点提升为新的主节点。

四大功能：

  1. 监控：不停 PING 主/从节点
  2. 通知：故障时通知管理员或程序
  3. 自动故障转移：主节点挂了 → 投票选一个从节点升级为新主节点 → 其他从节点改为跟新主节点同步
  4. 配置中心：客户端问 Sentinel “谁是主节点？”

解决问题：单机内存不够/性能不够，把数据分散到多台机器上。

十二、Lua 脚本（原子操作）

为什么用：多个命令需要原子执行（要么全做，要么全不做），比事务更强大。

Redis 7.0+ 推荐用 Redis Functions：

要点：脚本执行期间阻塞所有客户端，所以脚本要短小快速。

十三、Pipeline（管道 —— 性能优化利器）

问题：每条命令都要网络往返（RTT），100 条命令 = 100 次往返。

方案：把多条命令打包一次发出去，一次返回。

注意：Pipeline 不是原子的（和事务不同），命令之间可能穿插其他客户端的命令。

十四、常见场景实战大全

场景 1：缓存（最常见）

流程：查缓存 → 没有 → 查数据库 → 写缓存

缓存三大问题：

问题 解释 解决方案
缓存穿透 查一个不存在的数据，每次都穿透到数据库 ① 缓存空值 SET key "" EX 60 ② 布隆过滤器提前拦截
缓存击穿 一个热点 key 过期瞬间，大量请求打到数据库 ① 互斥锁（SET lock NX EX，只让一个请求去查库） ② 热点 key 永不过期 + 后台异步更新
缓存雪崩 大量 key 同时过期 / Redis 宕机，数据库被压垮 ① 过期时间加随机值 EX (3600 + random(0,300)) ② 多级缓存（本地缓存 + Redis） ③ 限流降级

缓存更新策略：

策略 怎么做 优缺点
Cache Aside（旁路缓存） 读：先读缓存，miss 则读 DB 写缓存；写：先更新 DB，再删缓存 ✅ 最常用、最推荐
Write Through（写穿透） 写操作同时写缓存和 DB 实现复杂
Write Behind（写回） 只写缓存，异步批量刷 DB 可能丢数据

十六、性能优化速查表

做法 说明
✅ 用 Pipeline 批量命令减少网络往返
✅ 用 SCAN 代替 KEYS *（不阻塞）
✅ 用 UNLINK 代替 DEL（异步删除大 key）
✅ 合理设 maxmemory 加淘汰策略，防止内存撑爆
✅ 设置过期时间 避免无用 key 永久占内存
❌ 避免大 key String value > 10KB，集合元素 > 10000
❌ 避免热 key 单个 key QPS 太高会成瓶颈
❌ 避免 O(N) 命令 HGETALL、SMEMBERS 元素多时很慢
